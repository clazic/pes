# 2~6단계 계획 승인 요약

- 읽는 사람: 한국어 정책 연구자(개발자 아님)
- 목적: 2~6단계 계획을 승인하기 전에 무엇이 달라지고, 무엇을 정해야 하는지 빠르게 확인
- 0단계는 확정됐고, 1단계 설계는 승인됐습니다. 이 문서는 2~6단계 승인용 요약입니다.
- 실제 `~/pes-projects`·`~/.pes/` 자료는 읽지 않았습니다. 모든 예시는 합성 자료입니다.

## 1. PES가 무엇으로 바뀌나

지금 PES는 프로젝트 폴더의 `project.json` 파일 하나에 모든 상태를 두고, AI가 만든 결과를 HTML 파일로 찍어 냅니다. 앞으로는 상태를 **데이터베이스(DB, 자료를 쌓아 두는 저장소)**에 쌓고, 화면과 AI 작업자가 같은 **API(프로그램끼리 주고받는 정해진 요청·응답 규칙)**로 일합니다. 사람은 웹 화면에서 답·승인·의견을 남기고, AI는 정해진 방식으로만 결과를 올립니다. 그래서 보고서의 2판·3판, 여러 사람, 다른 AI, 웹 이전이 가능해집니다.

용어: **A**는 PES가 AI를 직접 실행하는 방식, **B**는 Claude Code·Claude 앱·Codex CLI·OpenCode TUI 같은 외부 AI가 PES와 일하는 방식입니다. **이슈 하나 = PR 하나**는 작업을 한 번에 하나씩 검토·병합한다는 뜻입니다. **U1~U6**은 3단계, **U7~U12**는 4단계, **PR1~25**는 2·4단계, **WEB0~14**는 5단계, **E/M/H/X와 G3**는 6단계 작업 묶음입니다. CLI는 명령줄 도구, 스킬은 AI 작업 지침, TUI는 터미널 화면, worker는 작업자, 게이트는 단계 완료 확인, legacy는 이전 화면(`/legacy`), 계약 시험은 정해진 요청·응답이 같은지 보는 시험입니다.

## 2. 단계별로 무엇을 만들고, 끝나면 무엇이 달라지나

| 단계 | 무엇을 만드나 | 끝나면 달라지는 것 |
|---|---|---|
| 0. 기반 다지기 | 자동 테스트, 합성 자료, 개발 규칙, 기준선, 방식 A·B 시험 | 지금 기능을 바꾸지 않고 안전하게 고칠 수 있게 됩니다. |
| 1. 설계 | DB·API·화면·실행 구조 설계, 54개 표의 DDL(표 구조 정의) | 만들기 전에 약속을 문서로 확정합니다. 사용자 화면은 아직 바뀌지 않습니다. |
| 2. 새 뼈대(로컬) | 내 컴퓨터 안에서 도는 SQLite(작은 DB)와 API, 기존 프로젝트 이전, CLI·스킬·기존 화면 전환, **Claude Code·Claude 앱·Codex CLI·OpenCode TUI 연결** | 같은 6단계를 DB로 돌립니다. Codex/OpenCode TUI도 각각 한 라운드+재개를 합니다. 이전한 프로젝트의 `project.json`은 읽기 전용이 됩니다. |
| 3. 소통 기능 | 질문·답·결과 글·첨언·후속·인쇄를 한 작업 공간으로 | 질문 폼 대신 한 화면에서 한 라운드를 왕복합니다. 기존 화면은 계속 병행합니다. |
| 4. 판과 고급 소통 | 2·3판(같은 프로젝트의 다음 판), 이월, 판/라운드 비교, 갈림길 맛보기, AI 반대 의견, 직접 편집, 기본 화면 전환 | 끝난 보고서를 다음 판으로 잇거나 멈출 수 있습니다. 새 화면이 기본이 됩니다. |
| 5. 웹으로 옮기기 | Cloudflare(웹 서비스 회사) 무료 요금제 웹, 로그인·권한, AI 키, 내 컴퓨터 실행기, 알림, 웹 이전, 백업 | 어느 기기에서나 로그인해 답·승인합니다. 웹 DB(D1)와 파일 저장소(R2)로 옮깁니다. |
| 6. 넓히기 | 2단계에서 붙인 Codex/OpenCode TUI 회귀, 여러 사람·승인 담당자, 동시 편집, Linear/Notion 내보내기, 다중 worker, hc-team(AI 개발 팀), hwpx(한글 문서 파일 형식) | 팀과 여러 AI가 함께 씁니다. 한글(HWPX) 최종 확인을 합니다. |

## 3. 단계별 이슈 수와 대략의 순서

| 단계 | 이슈 수 | 대략의 순서 |
|---|---:|---|
| 0. 기반 다지기 | 10 | 테스트·자동 검사 → 기준선 → 방식 A·B 시험 |
| 1. 설계 | 4 | DB → API → 화면 → 실행 구조 (문서는 병렬) |
| 2. 새 뼈대 | 23 | PR1 스키마 → PR4 명령 서비스 → PR5·7·10 → PR13·14 API → PR17·18 → PR19·20a·20b → PR21·22 |
| 3. 소통 기능 | 9 | U1 틀 → U2 질문 → U3·U4 → U5·U6 → W1·R1(선택) → T1 실제 시험 |
| 4. 판과 고급 소통 | 9 | PR23 판 완료·이월 → PR24 비교·PR25 직접 편집(병렬 가능) → U7~U12 |
| 5. 웹으로 옮기기 | 15 | WEB0 언어 시험(2단계 진행 중, PR4·13 계약 픽스처 직후) → WEB1 → WEB2~4 → WEB5~9 → WEB10~12 → WEB13~14 |

- 표의 0~6단계 합계는 79개입니다. 여기에 표에 없는 기존·계획 이슈 17개를 더해 **전체 96개**이고, Linear 한도 260개에 **164개 여유**가 있습니다.
- **WEB0**은 번호만 5단계이고, 실제로는 **2단계 진행 중 PR4·13 계약 픽스처가 나온 직후**에 합니다. 웹에서 Python 코어를 그대로 쓸 수 있는지 미리 판정해 2~4단계 언어를 조정하는 작은 시험입니다.
- 3단계의 W1(브라우저 AI 도구 실험)과 R1(자동 재개)은 **선택**입니다. 하지 않아도 3단계 완료를 막지 않습니다.

| 위험 | 대비 |
|---|---|
