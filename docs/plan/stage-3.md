## 1. 목표

**질문 폼 페이지를 프로젝트 작업 공간 하나로 바꾸고, 한 라운드를 질문 → 답 → 결과 글 → 첨언 → 후속 → 인쇄까지 실제로 왕복하게 만든다.** 3단계가 끝나면 한국어 정책 연구자가 Windows에서 질문을 고치고, 가정·결정·반영 내역을 확인하고, 글에 첨언해 AI에게 묻고, 그 결과를 다음 라운드 할 일·글 수정·앞 단계 reopen으로 잇고, 라운드/단계/판을 골라 인쇄할 수 있어야 한다.

- **방식 A·B가 같은 DB·API·화면 문구·권한**을 쓴다. 다른 것은 실행 소유·전송·대기 표시뿐이다(UI 73).
- **2단계는 25개**(PR20을 20a·20b·20c로 나누고 PR26 언어 이전을 더함)를 전제로 하고, 3단계는 UI의 U1~U6과 새 이슈 5개(**REF1**·**MAT1**·W1·R1·T1)로 닫는다. **의존은 직선 순서가 아니라 DAG(4절)다.** 누적 이슈 수는 `roadmap.md` 2절 참고.
- 기존 대시보드·질문 폼은 같은 DB/API로 **병행**하고, 기본 진입 전환은 4단계로 미룬다.
- WebMCP는 **읽기·초안·첨언/답글만 플래그로** 실험하고, 자동 재개는 **기본 수동·opt-in**으로만 둔다.
- 3단계 비목표: 2판·3판, 판/라운드 비교, 직접 편집·제안 모드(Notion식), AI 반대 의견, 로그인·다중 사용자·웹 알림, Linear 실제 연동, hwpx 변환.
- **완료의 의미는 기능 목록이 아니라 증거**다. 합성 자료 왕복 + 사용자가 허용한 실제 프로젝트 1개 시험에서 자료 손실·답 유실·잘못된 승인이 없어야 한다.

### 2.2 작업 공간 틀(U1)과 기존 화면 병행

### 2.3 질문 작업면(U2)

**합의 계승 — 근거:** UI 결정 1·2·13, F02·F04; DB 3.4; API 18·55.

- 묶음 "답 검토 후 보내기"가 주 동작, 개별 제출은 보조. 당시 폼/질문 버전으로 원자 검증하고 충돌 시 부분 접수하지 않는다.
- 기본값 채택은 로컬 답 초안에만 들어가고 최종 제출 전에는 답이 아니다. 기본값·추천을 미리 답으로 채우지 않는다.
- 의견만 보내기와 의견으로 응답 인정(`allow_comment_as_answer`)을 구분한다. **허용/불허 두 사례**, 새 문구·선택지 확인 뒤 재답변을 인수 사례로 둔다.
- 질문 고치기=새 질문 버전+`재확인 필요`+옛 답 보존. 더하기·빼기·순서=새 폼. 빼기는 삭제가 아니라 철회/보류/합치기다.
- **중요도 표시·수정은 필수와 독립**이다. "중요하지만 선택", "보통이지만 필수" 합성 사례 2개로 검증한다(DB 84).
- 질문별 의견용 thread/message 최소 명령·조회를 U2가 만들고 U4가 재사용한다. 폼 발행·묶음 원자 제출도 U2 담당이다. 초안은 F04 준용.
- 이전된 합성 프로젝트(중요도 없음, `legacy_unverified` 승인, `__other` 스레드, 가정·결정 없음)가 깨지지 않고 "기록 없음"으로 보이는 사례를 완료에 넣는다.
- 에이전트 경로: 에이전트가 사람에게 질문을 게시하고 답을 읽는 API 명령+B MCP+A 내장 실행기 도구+스킬 절차(PR17). A·B 합성 라운드에서 실제로 만든다.

### 2.4 가정·결정·반영(U3)

**합의 계승 — 근거:** UI 결정 4, F03; DB 3.5, 11절 4·5(210–211줄); API 23.

- AI 제안, 사람 확인·채택. **사람이 가정을 고치는 경로**는 새 가정 버전(`revised`)+판단자(`assessment_actor_id`)+근거(`rationale`)이며 원문을 덮어쓰지 않는다.
- 가정·결정·반영은 표로 표시하고 버전·판단자·범위·근거 링크를 붙인다. 반영 내역은 다음 라운드 첫머리에 둔다.
- 결정은 프로젝트/판 범위를 나누고, 새 판에는 프로젝트 결정을 참조하고 판 결정은 당시 버전을 고정해 복사한다. 대체는 새 결정+`supersedes`이며 과거를 덮어쓰지 않는다.
- `applied/partial`은 **적용 tx + (결과 버전 또는 실제 적용된 후속 증거)**가 있어야 한다. 서비스가 결과·후속·tx의 의미 일치를 검증하며, FK 존재나 `proposed` 상태만으로 통과시키지 않는다(UI F03).
- "미제출"과 "0건"을 구분한다. `needs_review`는 새 판으로 복사돼도 자동 확인하지 않는다.

## 3. 방식 A·B 차이

- **A는 PES가 Go API를 직접 호출하고 Go 구독 사용량으로만 돌며, run마다 사용자가 고른 `opencode-go` 모델 하나(기본 `opencode-go/deepseek-v4.1-flash`), 폴백 없음.** **B는 Claude Code·Claude 앱·Codex CLI·OpenCode TUI·Codex 앱·OpenCode 앱 여섯 어댑터**를 같은 계약으로 묶는다. Claude Code는 6단계, 앱은 1단계 왕복·재접속, Codex CLI·OpenCode TUI·Codex 앱·OpenCode 앱은 변경 계약의 최소 왕복·재개를 확인한다. T1에서 Code를 먼저 하는 것은 다른 어댑터 시험을 빼는 뜻이 아니다(S0 7-2·7-3, 결정 0012·0013·0014, RUN A7·B2).

| 기능 | A (PES 내장 실행기 + Go 구독) | B (Claude Code·Claude 앱·Codex CLI·OpenCode TUI·Codex 앱·OpenCode 앱) | 공통 |
|---|---|---|---|
| U1 작업 공간 | PES가 run 상태를 앎 — 진행·대기·중단·권한 질문 표시 | 등록된 B run·입력 영수증·결과 채택 상태만 표시. 외부 프로세스 생존을 과장하지 않음 | 같은 화면·같은 문구·권한 |

- **방식**: **원본 프로젝트의 특정 스냅숏 버전을 가리키는 읽기 전용 참조**다. 복사본이 아니고 원본을 수정하지 않는다. 붙일 때 버전에 고정하고, 원본에 새 버전이 생기면 "새 버전 있음"을 표시하며 사람이 갱신을 고른다. 필요하면 붙일 때 스냅숏을 선택한다.
- **원본 없음·이전 경계**: 참조는 **`referenced_project_key`·`source_snapshot_key`**로 원본을 식별한다. 원본 스냅숏 삭제는 FK `SET NULL`에 기대지 않고 서비스가 `source_snapshot_id`/`latest_snapshot_id`를 **명시적으로 NULL로 만든 뒤 `status='source_missing'` tombstone**을 남기며, `source_label`·마지막으로 고정한 버전 등 식별자를 보존한다. **A만 이전/복원할 때 원본 프로젝트를 묵시적으로 함께 export하지 않고, "참조 원본 미포함" 상태를 표시**한다. 권한 회수·원본 없음·이전 미포함을 REF1·PR3/12·WEB9/10 시험에 연결한다.
- **표·명령**: 1단계 DDL 기준에 포함된 `project_references`(참조 프로젝트, 원본 프로젝트, `source_snapshot_id?`, `source_label`, `latest_snapshot_id?`, `scope_json`, 상태, 붙인 사람·시각, rev)를 사용하고, `reference_attach`·`reference_detach`·`reference_refresh` 명령·API·조회를 REF1이 소유한다. 프로젝트 생성 화면에서 고르는 UI도 포함한다.
- **권한**: **두 프로젝트 모두 접근 권한이 있는 사람만** 붙인다. 6단계 여러 사람일 때 참조 대상 권한이 없는 사람에게는 내용 대신 "권한 없음"을 표시한다.
- **전송**: 참고 원본 프로젝트가 Go 전송 OFF이면 그 참고자료는 A에서 Go로 보내지 않는다(**엄격한 쪽 우선**). B로 보낼 때도 원본의 허용 범위를 표시하고, 허용되지 않은 목적지로 보내지 않는다.
- **AI 제공**: 맥락 조립 때 참고자료 목록·요약을 넣고, 본문은 필요할 때 읽기 도구로 읽는다. 결과물에는 어느 프로젝트·어느 버전을 인용했는지 표시한다.
- **구분**: `/pes:start --import`(research-loop 조사를 참고자료로)와 2단계 PR11 legacy importer(이전·옮기기)와 다르다. REF1은 **참조**이며 원본을 복사·이전하지 않는다.
- **선행**: U1, PR 1·4·7·13·14.
- **완료 조건**: 붙임·떼기·갱신이 권한·멱등·tx/사건·영수증을 지킴. 원본 버전 고정, 새 버전 고지·사람 갱신, 원본 삭제 뒤 "원본 없음". 두 프로젝트 권한 없는 사용자에게 내용 비노출. Go OFF 원본의 참고자료가 A 호출에 포함되지 않음. 결과물 인용에 프로젝트·버전 표시. 웹·로컬 같은 API, 이전·import와 혼동 없음.

### MAT1 내 자료 올리기·글자 추출·AI 참조 스위치 (3단계, 새)

- **범위**: 프로젝트를 만들 때와 작업 중 언제든, hwp/hwpx/pdf/xlsx/xls/pptx/ppt/docx/doc/txt/md/csv 등 **내 자료를 올리고**, 형식별로 **AI가 읽을 글자·표를 추출**하며, **파일마다 AI 참조 허용/금지 스위치**를 둔다. A·B, 로컬·웹 모두 같은 API를 쓴다.
- **원본 보관**: 원본 파일은 그대로 보관(로컬 객체 저장소, 웹 R2 또는 Blob)하고 blob hash·크기·형식·버전을 기록한다. 기존 2단계 파일/결과물 계약(PR9 `version_files`·blobs)을 확장한다.
- **추출**: txt/md/csv는 그대로, docx·pptx·xlsx·hwpx는 내부 XML, pdf는 텍스트층을 뽑는다. **스캔 PDF OCR은 나중 선택**이다. hwp(옛 바이너리)·doc·ppt·xls는 추출 난이도가 높으므로 **"시험 후 결정"** 으로 두고, 안 되면 사람에게 hwpx/docx로 저장해 다시 올리라고 안내한다. 추출 실패·일부 손실은 숨기지 않고 `failed`/`partial`과 경고를 표시한다.
- **미리보기**: 추출 텍스트·표를 별도 버전으로 저장하고, 사람이 올린 뒤 **미리보기로 확인**한다. 원본과 추출본의 차이·누락을 표시한다.
- **AI 참조 스위치**: 파일마다 `allow`/`deny`, **기본값은 항상 allow**(2026-11-05 사용자 결정: 기본은 다 참조, 안 되는 것만 끈다). 프로젝트별 기본값은 두지 않는다. 올리는 화면과 자료 목록에서 바로 바꾸며, **소유자만** 변경하고 불변 이력을 남긴다.
- **정책 식별 단위**: 정책은 **`file_policies.id`**(blob 단위 안정 ID)를 기준으로 한다. `version_files.file_policy_id`·`file_ai_access_versions.file_policy_id`는 같은 blob의 정책을 가리킨다. `file_extractions.source_file_policy_id`(원본 blob)와 `text_file_policy_id`(추출 텍스트 blob)는 **각자 정책**을 가지며, 서비스가 원본 deny를 함께 검사해 **엄격한 쪽(deny) 우선**을 적용한다. 같은 blob(hash)을 새 버전·다른 role로 재첨부하면 같은 정책을 쓰고, 다른 blob인 추출본은 원본 정책을 자동 상속하지 않는다. owner만 재허용하고, 정책 없는 이력·blob 불일치·중복 정책은 FK/유일성으로 거부한다.
- **금지 파일 차단**: `deny` 파일은 **A의 Go 호출 맥락과 PES API/MCP/WebMCP 응답에서 내보내지 않는다.** 사람은 화면에서 보고 직접 인용할 수 있다. **B의 PC 동기화 폴더·로컬 파일은 Claude Code·Codex CLI·OpenCode가 파일/셸로 직접 읽을 수 있으므로, PES API/MCP 필터만으로 “A·B 모두 제외”를 보장하지 않는다.** 사람용 보관 영역과 AI 도구 workspace/도우미 자격을 분리하고 파일·셸·업로드 권한 통제 범위를 시험한다. 통제 불가 도구·경로는 연결 시 제한을 표시하고 “제외 보장”으로 쓰지 않는다. 금지로 바꿔도 이미 나간 내용은 회수 불가로 표시하고, 이후 맥락에서 제외하며, 금지 이전에 그 파일을 근거로 만든 결과물에 표시한다.
- **Go 전송과의 관계**: 프로젝트 Go OFF면 A는 호출하지 않고, Go ON이어도 파일이 `deny`면 그 파일은 보내지 않는다(**엄격한 쪽 우선**). `project_references`로 붙은 파일도 원본 프로젝트의 파일 스위치를 따른다.
- **AI 사용 방식**: 맥락에는 **허용 파일 목록·요약**을 넣고, 본문은 읽기 도구로 필요할 때 페이지·표 단위로 읽는다. 결과물에 근거 파일·위치 인용을 표시한다.
- **추출 위치**: 웹 무료 한도(Cloudflare step CPU 10ms 등) 때문에 **추출은 업로드하는 브라우저 쪽 또는 로컬**에서 하는 안을 기본으로 하고 WEB0에서 확인한다. 파일 크기·개수 상한을 둔다.
- **hwpx 출력과 구분**: hwpx **출력**(보고서 변환)은 여전히 6단계 맨 마지막이고, MAT1은 **입력 읽기**다. 서로 다른 이슈다.
- **선행**: U1, PR4·9·10·13·14.
- **완료 조건**: 올리기·버전/hash·미리보기·추출 성공/부분/실패/미지원 표시. **파일 정책 ID 기준**으로 allow/deny 변경이 소유자만·불변 이력·즉시 목록 반영. **같은 version/blob의 rendered·attachment·참조 원본 충돌은 엄격한 쪽 우선**, 재첨부는 같은 blob 정책, 추출본은 원본·텍스트 정책을 함께 검사해 엄격한 쪽. deny 파일이 A 호출·PES API/MCP/WebMCP 응답에 0건, 사람 화면에서는 열람·인용 가능. **B 여섯 도구의 로컬 직접 읽기·동기화 캐시·파일 OFF 뒤 재접속 경로를 시험하고, 통제 불가 경로는 “제외 보장”으로 표시하지 않음**. Go OFF·참조 원본 OFF가 엄격 우선. 결과물 인용에 파일·위치 표시. 옛 형식 hwp/doc/ppt/xls는 시험 결과와 안내가 남음. 크기·개수 상한과 무료 저장 한도 자기 제한.

- 3단계 종료 시 **기본 진입은 여전히 기존 화면**이다. 새 작업 공간은 권장 경로지만, 4단계에서 기존 읽기·답·승인·reopen·인쇄·딥링크가 합성+Windows/Mac에서 확인된 뒤 기본으로 바꾼다(UI 47).
