## 1. 1차 리뷰와 다르게 볼 것 (다른 회사 모델의 눈)

1차 리뷰가 본 목록을 되풀이하지 않는다. 아래에 힘을 쓴다.

| 볼 것 | 왜 |
|---|---|
| **동작 정확성** — 경계: 승인 뒤 다음 단계가 실제로 열리나(시안은 표시만 — 18.3-3) · 마지막 단계 승인(다음 단계 없음) · 질문이 모두 보내져 질문 단계가 사라진 뒤 · 다른 단계로 갔다 돌아옴 · 같은 요청 재확인(멱등) | 화면 흐름 바뀜(18.3)이 가장 잘 깨지는 곳 |
| **상태 꼬임** — 접힘 선택(sessionStorage) · “방금 보냄” 기억이 다른 프로젝트 · 다른 탭으로 새지 않나 | 전역 저장소를 새로 씀 |
| **초점 · 알림 순서** — 화면 읽기 사용자가 보낸 뒤 어디에 있나, 알림이 두 번 읽히지 않나 | 18.3-2 · 3.9 |
| **클래스 합치기** — 토큰과 색 클래스가 한 `cn`에 같이 있을 때 둘 다 남나 | 실제로 생겼던 버그(18.1) |
| **설계 일관성** — 같은 개념이 두 화면에서 다른 수 · 다른 말로 나오지 않나(예: 막힌 것 n vs 승인을 막는 것 n) · 확인할 수 없는 사실을 단정하는 문구(P4 — 18.6) | 18.3-4 · 18.6 |
| **시험의 질** — 시험이 실패할 수 있는 시험인가(기대값이 구현을 베끼지 않았나) | 모델 독립의 목적 |

## 2. 필수 / 권장

- **필수**: 잘못된 동작 · 데이터가 다른 프로젝트로 샘 · 접근성 퇴보 · 설계와 다름 · 시험이 아무것도 지키지 않음 · 비밀/실제 자료.
- **권장**: 더 단순한 구조 · 이름 · 작은 중복. 권장만 있으면 승인.

## 3. 두 번째 리뷰

- 첫 리뷰의 필수 항목이 고쳐졌는지와 그 고침이 만든 새 변경만 본다. 두 번째에도 필수가 남으면 leader가 사용자에게 넘긴다(세 번째 리뷰 없음).
