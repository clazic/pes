## 1. 목표

질문 폼 페이지를 **프로젝트 작업 공간 하나**로 바꾼다. AI 질문은 중심에 두되 사람이 질문을 고치고, 글에 첨언하고, AI와 대화하고, 그 결과가 어떻게 반영됐는지 한 화면에서 본다. 근거·버전·누가 했는지로 되짚을 수 있는 **연구 작업대**.

## 2. 화면 구조

```text
프로젝트 / 1판     조사 · R2     방식 A · 답변 기다림
Go 전송 허용 [켜짐] [전송 내역]       [결정 기록] [명령 찾기 Ctrl+K] [인쇄]
──────────────────────────────────────────────────────────────────
단계·라운드       결과 글 + 첨언                 질문 | 가정 | 대화
기획 · 승인       이번 라운드 반영 내역           답할 질문 2 / 전체 5
조사 · 현재       결과 제목 · 버전 · 작성자       Q-12 중요 · 필수
  R1             본문·표·근거                    질문 문구 [고치기]
  R2             선택 → 첨언 / AI에게 묻기 / 할 일로   선택지 / 질문별 의견
분석·종합 …      여백의 첨언 번호                [기본값 채택] [답 검토 후 보내기]
```

- **배치(검증용 시작값, 유효 CSS 폭 기준)**: ≥1440 3영역 / 1280~1439 탐색을 아이콘 줄로 접고 결과+질문 / <1280 한 열(탭, 열린 질문이 기본). 1366·1440·200% 확대에서 긴 한글 질문·본문·표로 확인. 아이콘 줄에도 이름·상태·키보드 입구
- **열린 질문이 있으면 질문이 기본**, "질문에 집중" 전환, 미응답·재확인 배지는 탭 밖에도
- 헤더: 프로젝트·판·보는 단계/라운드·실행 담당·Go 정책. 과거 라운드를 볼 땐 "현재 진행: 조사 R2"를 따로 표시
- 단계 시작 질문은 `round_id=NULL` → "단계 시작"으로 표시, 가짜 R0 없음
- 스크롤 영역 중첩 없음, 고정 헤더가 입력·초점을 가리지 않음

## 3. 합의된 결정

| # | 주제 | 결정 |
|---|---|---|
| 1 | 질문 작업면 | 질문 카드에서 **고치기 = 새 질문 버전, 더하기·빼기·순서 = 새 폼**, 옛 답 보존. 중요도와 필수는 별개. **기본값·추천은 미리 답으로 채우지 않음. "기본값 채택"은 그 값을 로컬 답 초안에 넣는 동작이고, 최종 제출이 확정돼야 답이 됨** |
| 2 | 답 제출 | **"답 검토 후 보내기"(묶음)가 주 동작** — 당시 폼/질문 버전과 답·응답으로 인정한 의견을 한 제출 단위로 검증, 충돌 시 부분 접수 안 함. **개별 답 제출은 새 기능**(다른 필수 질문까지 끝났다고 하지 않음). 의견만 보내기와 "의견으로 응답 인정"(`allow_comment_as_answer`)을 구분 |
| 3 | 결과 글 | **읽기 전용 + 선택 도구**(첨언 / AI에게 묻기 / 할 일로). 앵커 exact/moved/ambiguous/lost를 숨기지 않음. 3단계에도 **첨언 → AI 글 수정 제안(`edit_text`) → 기반 대조 → 새 버전 채택**은 됨(원문 덮어쓰기 없음). 직접 편집·제안 모드는 4단계 |
| 4 | 가정·결정·반영 | **표.** 해결 ≠ 적용, applied는 결과 버전·tx 증거 필수. 반영 내역은 "미제출"과 "0건"을 구분 |
| 5 | 명령 메뉴 | **Ctrl/Cmd+K 하나의 동작 목록**(명령·맥락 메뉴·단축키 공통). AI 전환은 **명시적 모드 버튼**, Tab 전환은 IME 조합 밖의 보조. 검색 결과 없음을 AI 전송으로 바꾸지 않음. 사람 권한 동작은 메뉴를 거쳐도 서버 검사 |
| 6 | 프롬프트로 복사 | **방식 B의 기본 수동 전달 통로.** Claude Code·Claude 앱의 실제 연결을 대체하지 않음. 포함·제외·경고 미리보기, "복사됨" ≠ 접수·수신·실행·반영. 클립보드 실패 시 직접 선택 대안 |
| 7 | B의 "AI에게 묻기" | **PES에 접수된 사람→AI 질문과 처리 상태 조회**(브라우저 큐·새 표 아님). 등록·복사·외부 수신·답 수신을 구분, 경과 시간 표시. 이것만으로 run을 `waiting_human`으로 만들지 않음 |
| 8 | 전송 허용 | 칩 **항상 표시**, 끄기 스위치는 **소유자 사람만**, 끄기가 이미 나간 자료를 회수하지 않음을 확인 대화·도움말·기록에 반복 |
| 9 | 상태 분리 | 전송 허용 / 실행 / 답 제출 / 단계 승인 / 반영 완료는 다른 사실 — 버튼·문구도 나눔. 제출·승인·정책 변경은 **서버 영수증 뒤에만 성공 표시** |
| 10 | 인쇄 | 라운드/단계/판(기본 = 현재 판 6단계, 모든 판은 고급). 봉인·승인본은 그 스냅샷, **열린 라운드도 출력 시점의 저장 버전·사건 경계·manifest를 고정하고 출력물 보존**(인쇄 때문에 봉인하지 않음). 미제출 초안 제외. A4·표 머리 반복·흑백 대비 |
| 11 | "할 일로" | **PES 다음 라운드 할 일이 기본.** Linear는 3단계엔 초안·복사만, 실제 연동은 6단계. 연구 내용 자동 포함 안 함 |
| 12 | 기존 화면 | 3단계엔 기존 대시보드·질문 폼과 **병행**(같은 DB/API, 이중 쓰기 아님). 기본 진입 전환은 **기존 읽기·답·승인·reopen·인쇄·딥링크가 합성 자료와 Windows/Mac에서 확인된 뒤**(4단계 목표). 기존 ask 링크는 당시 set/버전으로 연결 |
| 13 | 초안 | **같은 탭(새로고침 포함, 브라우저 저장소)**. 서버 초안 API 없음 |

## 4. 기술

- **서버 렌더 + ES 모듈 섬.** 사용자에게 화면 빌드·Node 서버를 추가로 요구하지 않음(개발 빌드까지 금지하지는 않음). 셸·목록·질문 카드·표·인쇄는 서버 HTML, 명령 메뉴·선택 도구·질문 편집·초안·갱신만 JS
- 현행은 Python이 제목·JSON을 넣고 브라우저가 본문을 그리는 구조라, 완성된 서버 렌더를 그대로 재사용한다고 보지 않음
- Python/웹(Workers) 템플릿 공유는 **U1의 제한된 시험(상한 약 1주)**으로 판단. 안 되면 JSON + 얇은 클라이언트 렌더로 가되 첫 표시·딥링크·인쇄 요구를 다시 대조, HTML 포크는 안 함
- 화면 데이터·명령 계약은 렌더러와 분리, 브라우저는 DB를 직접 읽거나 쓰지 않음
- 저장 Markdown·외부 인용은 안전하게 렌더(스크립트·이벤트 속성·위험 URL 차단)
- WebMCP는 기본 경로가 아님 — ② API의 허용 목록을 따르는 얇은 선택 층, 3단계 실험

## 5. 방식 A·B 차이

| | A (PES 안 OpenCode) | B (Claude Code·Claude 앱) |
|---|---|---|
| 실행 상태 | PES가 실제 run 상태를 앎 — 진행·대기·중단·권한 질문 표시 | **PES에 등록된 B run·입력 영수증·결과 채택 상태는 공통 API로 표시.** 외부 프로세스의 실제 생존·중단은 확인된 범위만, "연결됨"을 과장하지 않음 |
| AI에게 묻기 | 명시적 실행 동작으로 A run 시작 | 질문 접수 + 프롬프트 복사 + 수신/답 상태 |
| 실행 권한 질문 | OpenCode permission/form을 연구 질문과 **구분해** 표시 | Claude Code·앱 쪽에서 처리 |
| 사람 답 대기 | `waiting_human` + lease 해제 | 같음. 수신과 읽음을 구분, Claude 앱 지속 연결·heartbeat를 가정하지 않음 |
| Go 칩 | 의미 있음(차단) | 표시는 유지(B는 Go로 보내지 않음을 설명) |

같은 DB 상태면 같은 화면 문구·버튼·권한(PR 21 교차 계약).

## 6. 시험

- `pytest`(서버 렌더 HTML·상태 전이) + **Playwright 스모크(개발 전용)**. **필수 Windows CI는 브라우저를 설치해 실행하고 없으면 실패**(건너뛰지 않음). 매 PR/main Windows+macOS
- 자동: 답·충돌·초안·키보드·인쇄 핵심. **수동 병행**: 실제 Windows 한글 IME·NVDA·인쇄 쪽 나눔. 스크린샷 기준선 없음

| F05 | ambiguous/lost에도 **인용문·원래 버전 보존**, 자동 후보 확정·삭제 금지, **원래 앵커 불변**, 현재 위치는 새 판정 또는 새 앵커 계보에서 조회. thread_versions에 anchor 열이 있다고 가정하지 않음(U4 인수 조건, 부족하면 DB·API로) |
| F06 | 타임아웃은 **"접수 확인 중"**, 같은 요청 키로 확인. rev 충돌·0행·부분 실패면 성공 표시 금지·초안 유지. 즉시 반영은 펼침·로컬 초안만. 과거 승인과 stale을 함께 표시 |
| F07 | Go 칩: 정책 누락·손상 → **"차단 중"**, 변경 확정 전 → **"변경 중"**, 진행 중 전송의 취소 시도·unknown 표시, 재허용 뒤 자동 재시작 없음 안내. B 화면의 표시가 실제 Go 목적지 검사를 우회하지 않음 |
| F08 | 접근성 인수 조건: 대비, **초점 복귀·Tab 덫 방지**, 좁은 배치 전환 때 초안·스크롤 보존, 데스크톱 200% 확대를 모바일 제한으로 오인해 핵심 동작을 숨기지 않음. 모바일에서도 필수 답·의견으로 응답·오류 확인·복사 대안 가능 |
| F09 | 프롬프트에 미제출 내용을 넣으면 **"미제출 초안"으로 표시**, 실제 로컬 파일 경로는 넣지 않음(U5) |
| F10 | 모든 판 인쇄: 포함 판·분량을 먼저 확인하고 **판별 고정 manifest를 묶음**. DDL에 없는 프로젝트 전체 scope를 가정하지 않음. 토큰 스트림 기본 제외 |
| F11 | 기존 화면 병행: **빠른 답·장애 대비 경로와 내보낸 고정 HTML을 구분해 보존** |
| F12 | Linear(6단계): 기본 payload = **제목 + 사람이 쓴 요약**. 외부 참조·중복 방지 키·응답 유실 후 확인·영속 영수증을 DB·API에서 합의한 뒤 실제 연동. Go 전송 기록·정책을 재사용하지 않음. 외부 완료 ≠ PES 적용·승인, 왕복 동기화 없음 |
