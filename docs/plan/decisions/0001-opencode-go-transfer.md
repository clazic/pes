# 0001. OpenCode Go에 비공개 연구 자료 전송 허용

- 날짜: 2026-11-04
- 담당: SEL-21·22(1단계 DB·API), SEL-18(방식 A 시험)

## 문제

방식 A(PES 내장 실행기가 OpenCode Go API를 직접 호출)가 연구 맥락·원고를 모델에 보내야 작업이 된다. 그런데 비공개 연구 자료가 외부로 나가는 경로이므로, 프로젝트마다 민감도가 다른 자료를 사용자가 통제할 수 있어야 한다. 전면 금지는 A를 쓸 수 없게 하고, 전면 허용은 민감한 프로젝트를 막을 수 없다.

## 선택지

1. 비공개 자료 전송을 금지한다.
2. 항상 허용하고 프로젝트별 설정을 두지 않는다.
3. 보내는 방향으로 기본 허용하되 프로젝트별로 끌 수 있게 한다.

## 채택

3번. **기본 켜짐 + 프로젝트별 끄기.** 0단계 시험은 합성 자료만 쓴다. 끄면 맥락·요약·첨부·재시도까지 막고, 정책이 없거나 손상되면 거부한다. 합성 자료라고 우회하지 않는다.

## 이유

- 방식 A를 바로 쓸 수 있으면서, 민감한 프로젝트는 사용자가 끌 수 있다.
- 허용은 자동 실행이 아니고, 이미 나간 자료는 회수 보장이 없다. 그래서 기본값만 허용하고 프로젝트 경계에서 통제한다.
- 정책 부재를 허용으로 해석하면 사고가 나므로 fail-closed로 둔다.

## 영향

- `stage-1-db.md` 결정 1, `stage-1-api.md` 결정 15(Go OFF)가 이 결정을 구현한다.
- 1단계 DB·API에 프로젝트별 설정, 2단계 run·전송 경로 검사, 5단계 웹 이전에도 같은 정책을 승계한다.
- 실제 자료·키는 시험·로그·공개 저장소에 넣지 않는다(0008).

## 재검토 조건

- 기관 규정이 외부 전송 자체를 금지할 때.
- 유출·사고가 확인되거나, 5단계에서 자료 위치·관할을 정할 때.
- 모델·전송 경로가 바뀌어 정책 검사 지점이 달라질 때.
