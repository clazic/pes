# 0019. 방식 A의 AI는 사용자가 직접 등록한 AI 연결을 쓴다 (0013 일부 대체)

- 날짜: 2026-11-10 (사용자 결정 2026-11-05를 기록)
- 담당: 2단계 PR19(실행기·사용량) · PR10(정책), 5단계 WEB4(키 관리) · WEB7 · WEB12(웹 화면). 기록: Claude(Opus 5.5)
- 상태: **채택(사용자 결정 2026-11-05)** — 세부(아래 "정할 것")는 PR19·PR10에서 확정. Codex 검수 전.
- 대체: [0013](0013-mode-a-go-subscription-and-model-choice.md)의 "제공사는 OpenCode Go 하나" 부분만 대체한다. 0013의 나머지(직접 호출, 호출 시도·멱등, 내장 에이전트 루프와 도구 allowlist, 사용량 보호, 폴백 없음)는 그대로다.
- 설계: [ui/dashboard-v2.md](../ui/dashboard-v2.md) 13.2 · 1.3 · 8절 31 · 10절 질문 7 · 시안 `mockups/dashboard-v2-react`의 `AddConnectionDialog`

## 문제

0013은 방식 A가 부를 AI를 **OpenCode Go 구독 하나**로 정했다. 2026-11-05 사용자가 "특정 서비스에 묶지 말고, 사용자가 AI 연결을 직접 등록하게 하라"고 정했다. 그러면 제공사·과금 방식이 여러 가지가 되므로, 0013의 Go 전용 규칙(구독 3구간 계기·추가 요금 확인·기준점)을 어디까지 일반화할지와, 실제 돈이 드는 "쓴 만큼 과금" 연결을 어떻게 막을지를 정해야 한다.

## 선택지

1. 0013 유지 — OpenCode Go 하나만.
2. **사용자가 AI 연결을 직접 등록** — 종류·주소·키·모델·과금 방식을 사람이 넣고, 과금 방식별로 보호 규칙을 둔다.
3. 제공사 몇 개를 PES에 미리 넣어 두고 고르게 한다.

## 채택

**2번.**

- **등록 항목**: 종류(구독형 API · OpenAI 호환 API · Anthropic API · Google API · 직접 입력(내 컴퓨터·로컬 모델 등)) · 이름 · 주소 · API 키 · 모델(목록 불러오기 또는 직접 입력) · 과금 방식(**구독 한도 안** / **쓴 만큼 과금**).
- **연결 시험은 PES 서버가 한다.** 브라우저가 외부 API를 직접 부르지 않는다. 저장 전에 통과해야 한다.
- **구독 한도 안**: 0013의 사용량 보호(3구간 추정 · 멈춤 문턱 기본 90% · 추가 요금 꺼짐 확인 · 계정 기준점 · 호출 전 예약 · unknown 보존)를 **연결마다** 둔다.
- **쓴 만큼 과금**: **비용 상한이 없으면 저장도 실행도 하지 않는다.** 추정 비용 = PES가 센 토큰 × 모델 단가이고, **단가를 모르는 모델로는 시작하지 않는다**(0으로 두지 않음). 다음 호출 예약을 더해 상한을 넘으면 **보내기 전에** 멈춘다. 같은 키를 다른 곳에서 쓰면 그 비용은 PES가 모른다고 화면에 적고, 제공사 콘솔에도 한도를 걸라고 안내한다.
- **키**: 입력 뒤 다시 보이지 않는다(끝 4자리·저장 위치·바꾼 사람·시각만). 로컬은 OS 키체인, 웹은 서버 비밀 저장소. 화면·로그·사건·프롬프트·내보내기·응답 DTO에 남기지 않는다.
- **권한**: 등록·변경·지우기는 사람(연결 관리자)만, 요청 한 건마다 재인증. 에이전트 키로는 못 한다.
- **프로젝트마다 연결·모델을 고른다.** 실행 하나는 고른 모델 하나로만 가고, 실패해도 다른 모델·연결로 바꾸지 않는다(0013 폴백 없음 유지). 바꾸면 다음 실행부터.
- **"AI가 읽기"와 파일별 AI 참조는 모든 연결에 똑같이** 적용한다(로컬 모델도 같은 스위치).
- 화면 문구는 제공사 이름이나 "Go"를 쓰지 않고 "AI 연결"·"API"라고 쓴다.

## 이유

- 사용자가 정했다(2026-11-05). 한 서비스의 요금·이용 조건·장애에 PES 전체가 묶이지 않는다.
- 0013의 보호 장치는 그대로 살린다. 구독형은 같은 규칙을 연결마다 적용하고, 쓴 만큼 과금은 "상한 필수·단가 모르면 시작 안 함·보내기 전에 멈춤"으로 실제 비용을 막는다.
- 3번(미리 넣은 제공사)은 목록을 PES가 계속 따라가야 하고, 결국 "직접 입력"이 필요해진다.

**확정(2026-11-11, PR19 SEL-52)**: 위 1~4는 [stage-2-db-guarantees.md 8.16](../stage-2-db-guarantees.md)에 확정했다(요청 형식 `openai_compatible`·`anthropic` 구현, Google 미지원, 구독형 사용량 공식 API 미확인, 단가는 사람 입력·run 시작 때 스냅샷, 명령·표 이름). 사용 방법은 [docs/adapters/a-builtin.md](../../adapters/a-builtin.md).

**보강(2026-11-11, SEL-52 최종 리뷰 1/2 F4)**: 구독 연결의 "추가 요금 꺼짐 확인 · 계정 기준점"은 연결마다 사람 전용 명령(`ai_connection.confirm_extra_charge_off` — 계정 범위·유효 기간, `ai_connection.record_usage_baseline` — 사용량 기준점)으로 기록하고, 둘 중 하나라도 없거나 확인이 만료·확인 불가이거나 확인 뒤 답에 과금 신호가 보이면 호출 전에 멈춘다(`extra_usage_off`). 답의 과금 신호는 관측값 그대로 `billing_source`에 기록한다(연결 설정값을 쓰지 않는다). 자세한 내용은 8.16·어댑터 노트.

**보강(2026-11-11, SEL-52 최종 리뷰 2/2 N1~N6)**: ① 키 반사 검사는 답의 모든 문자열을 `\uXXXX`(여러 겹)·`%xx`·base64로 벗겨 가며 보고, 도구 인자는 두 번째 JSON 해석 결과까지 본다. 모델 목록 응답도 같은 검사를 거쳐 반사가 있으면 연결 시험 실패(`key_in_reply`)이고 아무것도 저장하지 않는다. ② 실행기·연결 시험은 주소와 키를 키·주소 변경과 같은 연결별 잠금 아래에서 함께 읽고 키 끝 4자리를 대조한다. ③ 키나 주소를 바꾸면 연결의 `credential_rev`가 오르고, 그 전의 추가 요금 꺼짐 확인·기준점은 세지 않는다(새 키가 어느 계정인지 PES가 판별할 수 없으므로 승계할 근거가 없다). ④ `unknown`으로 정산되는 모든 경로에서 답의 과금 신호를 보존하고, 사람의 호출 정리(청구됨/안 됨)는 계정 재확인을 대신하지 않는다. ⑤ 모양을 읽을 수 없는 답은 `unknown` + `usage_unknown`이다. 표 열 추가(`credential_rev` 3곳)는 마이그레이션 002 안이며 PR의 사람 확인 대상이다.
