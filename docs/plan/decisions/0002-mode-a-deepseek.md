# 0002. 방식 A는 연구 6단계 전체를 DeepSeek 하나로 통일

- 날짜: 2026-11-04
- 담당: SEL-24(실행 구조), SEL-18(방식 A 시험)

## 문제

방식 A의 모델을 역할별로 나눌지, 하나로 둘지 정해야 한다. 모델을 나누면 품질·비용을 역할에 맞출 수 있지만, 재현·비용·장애 대응이 복잡해지고 폴백 경로가 생긴다.

## 선택지

1. 역할별로 다른 모델을 쓴다.
2. 연구 6단계(plan~publish) 전체를 DeepSeek 하나로 통일한다.
3. 여러 provider를 두고 run마다 고른다.

## 채택

2번. **연구 6단계 전체를 `opencode-go/deepseek-v4.1-flash` 하나로** 통일한다. 모델 역할 나누기는 시험 결과를 보고 나중에 다시 정한다.

## 이유

- 비용·재현성·운영이 단순하고, run마다 모델이 달라져 결과를 비교하기 어려운 문제를 피한다.
- 폴백을 두지 않아 "조용히 다른 모델로 넘어감"을 막는다.
- 0단계 시험과 2단계 A 어댑터를 같은 전제로 시험할 수 있다.

## 영향

- `stage-1-runners.md`, `stage-1-db.md`의 `runs` CHECK(A는 `opencode-go`/DeepSeek), 2단계 PR 19.
- 비용 상한은 SEL-18 측정 뒤 사용자 확인이다. 상한이 없으면 유료 실행을 시작하지 않는다.
- 5단계 웹 이전에도 A 모델 전제를 승계한다(0005).

## 재검토 조건

- DeepSeek 품질이 6단계 작업에 부족하다고 확인될 때.
- 가격·정책·모델 제공이 바뀌어 같은 전제를 유지할 수 없을 때.
- 역할 분리가 비용·품질에서 분명한 이득을 보일 때.
