# PES 재설계 배경 (2026-11-04 사용자와 나눈 이야기)

이 문서는 PES 재설계 논의에 참여하는 AI(Claude·Codex·OpenCode)가 함께 읽는 배경이다. 저장소는 `~/projects/pes`(GitHub `clazic/pes`). 2026-11-04에 비공개로 바꿨다가, CI를 매 PR 돌리려고 **다시 공개로 되돌렸다**(사용자 결정). 공개 저장소이므로 실키·기관 자료·실제 프로젝트 내용을 넣지 않는다. 현재 버전 0.15.6.

## 1. 지금의 PES

- Claude Code 플러그인. 프로젝트 하나를 **기획 → 조사 → 분석·종합 → 집필 → 검증 → 산출·공유** 6단계로 진행해 보고서·작업물을 만든다.
- 단계마다 라운드 1→2→3…을 돌고, 사람이 답·승인하면 다음 단계로 간다. `reopen <단계>`로 앞 단계를 다시 열 수 있다(뒤 단계에 "다시 확인 필요" 표시).
- 구조: `scripts/pes.py`(CLI, 약 1700줄)가 프로젝트 폴더의 `project.json`과 파일을 관리하고, AI가 만든 JSON을 `templates/*.html`에 넣어 **정적 HTML**(`index.html`, `ask-*.html`)로 찍어 낸다. `scripts/serve.py`(127.0.0.1:8760)가 그 파일을 보여 주고 `POST /feedback`으로 답을 한 번 받는다. 화면은 `/version`을 보고 새로 고친다.
- 스킬: `skills/{core,plan,research,analyze,write,verify,publish,...}/SKILL.md`. 서브에이전트: researcher·reviewer·verifier·writer.
- 테스트가 전혀 없다.
- 사용자: 한국어 정책 연구자(울산연구원 보고서 등), Windows 주 사용, Mac(m5)에서도 사용. 이모지 최소, 정렬된 표·같은 크기 카드를 좋아함.

## 2. 사용자가 원하는 방향

1. **판(edition)**: 보고서가 끝난 뒤 같은 프로젝트 안에서 2판·3판으로 이어 가거나 멈춘다. 이어 갈 때는 앞 판 결과를 바탕으로, 일부를 빼고, 기획부터 다시 할 수 있다.
2. **웹 PES + 에이전트 API**: PES를 Vercel 또는 Cloudflare에서 돌리고, AI 에이전트는 정해진 형식으로 API에 작업물을 올린다. 여기서 API는 "AI를 구독/API로 쓰는 방식"이 아니라 **웹 PES와 에이전트가 주고받는 인터페이스**다.
3. **사람은 웹 대시보드에서 답하고 승인한다.**
4. **질문 목록**: 라운드마다 AI가 사람에게 묻는 질문과 사람이 AI에게 묻는 질문을 빼고·더하고·고치기 좋은 구조.
5. **AI 질문 폼은 매우 중요**(생각지 못한 방향을 열어 줌). 다만 지금은 폼에 갇힌다. (정정: 질문별 덧붙임 칸 `__other`는 `templates/_questions.html`에 이미 있다 — Codex 확인.) 없는 것은 질문 문구·선택지 살짝 고치기, 질문 더하기·빼기, 질문을 두고 AI와 주고받기다.
6. **첨언**: 써진 글의 특정 부분에 의견을 달고, 그 첨언을 두고 AI와 대화하며 프로젝트를 키운다. 대화 결과는 글 수정 / 다음 라운드 할 일 / 앞 단계 다시 열기로 이어진다.
7. **인쇄**: 라운드·단계·전체를 골라 보기 좋게 인쇄(지금은 최종 보고서·단계 보고서만 인쇄 스타일 있음).
8. **사람-AI 소통 아이디어(모두 채택)**
   1. AI가 깔고 있는 가정 목록을 드러내고 사람이 맞다/틀리다/고침
   2. 내 의견이 어떻게 반영됐는지(반영 내역)를 다음 라운드 첫머리에
   3. 질문마다 중요도와 기본값
   4. 갈림길에서 방향 2~3개를 맛보기로
   5. 근거와 맞지 않는 요청에 AI가 반대 의견
   6. "정해진 것" 목록을 프로젝트 전체의 살아 있는 결정 기록으로
   7. 웹 이전 후 알림
9. **데이터베이스 설계가 필요**하다(덮어쓰지 않고 쌓기, 첨언 위치는 인용문으로, 큰 파일은 저장소에, 로컬과 웹이 같은 설계). Claude 추천: Cloudflare D1(SQLite) + R2, 로컬은 SQLite.
10. 계획 문서·개발 소스를 모두 `~/projects/pes` 한 저장소에 둔다(`docs/plan`, `docs/archive`, 이후 `web/`, `tests/`).
11. Notion·Linear의 동작(동적 이동, 이슈 등록 등)을 분석해 PES 기능 아이디어로 삼는다.

## 3. 두 가지 운영 방식 (둘 다 개발)

- **방식 A — PES 내부 에이전트**: PES 시스템 안에서 AI 에이전트가 기획부터 발간까지 수행한다. 사용자가 구독 중인 **OpenCode Go**(opencode의 저가 모델 구독, 예: `opencode-go/deepseek-v4.1-flash`)를 opencode 서버의 API로 PES가 직접 호출하는 방식.
- **방식 B — 외부 에이전트 + PES 소통**: 지금처럼 작업은 터미널(TUI)에서 Claude Code·Codex 등이 하고, 사람과의 소통·기록은 PES(웹 대시보드 + API)가 맡는다.
- 두 방식이 **같은 데이터 모델과 같은 API 형식**을 쓰게 하는 것이 목표다.

## 4. 큰 개발 단계 (초안, 사용자 승인)

| 단계 | 목표 |
|---|---|
| 0. 기반 다지기 | 지금 PES를 안전하게 바꿀 수 있게(테스트, AGENTS.md, research-loop 저장소). **hwpx 변환 확인은 맨 마지막으로 미룸** |
| 1. 설계 | 방향, DB, API 형식, 작업 공간 화면 설계를 문서로 확정 |
| 2. 새 뼈대(로컬) | 정적 파일 → DB+API. 기존 프로젝트 이전, 스킬이 API로 일하게 |
| 3. 소통 기능 | 질문 편집·질문별 의견, 가정, 반영 내역, 중요도·기본값, 결정 기록, 첨언·대화, 범위 인쇄 |
| 4. 판과 고급 소통 | 2판·3판, 갈림길 맛보기, AI 반대 의견 |
| 5. 웹으로 옮기기 | Cloudflare(Workers·D1·R2), 로그인·권한, 에이전트 키, 알림 |
| 6. 넓히기 | 여러 에이전트·여러 사람, hc-team으로 PES 개발 |

지금 하지 않기로 한 것: 현재 정적 템플릿의 카드 디자인 개선(새 화면 설계에 합침, 자료는 `docs/archive/card-redesign/`).

## 5. 논의 방법

각 단계마다 (1) 생각해야 할 주제를 뽑고, (2) 주제마다 무엇을 정해야 하는지와 어떻게 정할지(기준·선택지)를 정한다. 방식 A와 B를 나눠 차이를 적는다. 각 AI의 의견은 `docs/plan/discussion/stage-<N>-<이름>.md`에 쓰고, Claude가 종합해 `docs/plan/stage-<N>.md` 설계서로 만든다.
