## G1~G26의 인계 판단

- **G1·G2·G4·G11·G22·G23**은 핵심 동작/안전 계약이다. 새 표의 필요 여부 자체를 지금 단정할 필요는 없지만 저장 범위·명령·권한·원자성·검증 담당은 F03/04/06/11처럼 닫아야 한다. 업로드 기본 allow는 유지하며 새 deny 파일과 기존 blob 재첨부를 다르게 처리한다.
- **G3·G5·G6·G7·G24**는 화면/읽기 계약의 담당 빈칸이다. 기존 PR/U/WEB 안에 배정하거나 해당 단계 보류를 명시한다. 상태 표마다 새 이슈를 만들 필요는 없다. 현재 101개 집계에 v2 이슈가 자동 추가됐다고 보지 않는다.
- **G8·G12·G13·G18**은 의미·인가 결정이다. 사람이 더한 연구 폼 질문의 작성자와 질문 방향을 구분하고, editor 실행 권한·참고 원본 허용·Go 목적지 미확인을 허용으로 추정하지 않는다. G13은 현행 “두 프로젝트 접근 권한” 계약을 몰래 강화하는 대신 개정 여부를 명시한다.
- **G9·G10·G17·G20·G21·G25·G26**은 범위/표시/사건 인계다. 모바일 확대와 알림 우선은 개정으로, Go 꺼짐 분리·주의 색은 보강으로 다룰 수 있다. 추가 알림과 A 실행 세부 상태는 저빈도·측정된 사건에만 연결하고, R1은 사용량 차단을 자동 해제하지 않는다.
- **G14·G15·G16·G19**는 화면과 정책의 대응을 정리할 일이다. 구독 사용량과 프로젝트 문턱은 별개이며 계기의 최소 문턱이 모든 프로젝트를 전역 차단하는 정책이 되면 안 된다. 단계 명칭은 현행 6단계를 승계하고, extra_usage_off는 “꺼짐 확인 필요”로 읽는 것이 맞다. DB 값 이름을 지금 바꾸지 않아도 된다.
