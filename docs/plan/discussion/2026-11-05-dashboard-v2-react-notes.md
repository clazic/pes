## 1. 옮기며 바뀐 점(정적 HTML → React)

## 5. 계획과 어긋나는 곳(고치지 않음 — 이슈 착수 때 맞춤)

1. **화면 기술**: stage-1-ui 4절·6절, stage-3 U1·공통 시험, stage-5 WEB1의 “서버 렌더 + ES 모듈 섬 / 템플릿 공유 시험 / TS 서버 렌더 테스트” → 0017(정적 앱 + API). 2단계 PR18은 계획 그대로(기존 화면 동등 전환).
2. **읽기 경로**: SPA는 화면마다 JSON 읽기가 필요하다(프로젝트 목록 G24 · 사용량 · AI 연결 · 내 컴퓨터 · 알림) — 2단계 닫힌 목록에 없는 것이 있다.
3. **배포물**: 플러그인이 git 태그로 배포되므로 `dist/`를 배포물에 넣는 방법이 필요(PR26·U1).
4. **0013**: 제공사 하나(OpenCode 구독) 고정 → AI 연결 수동 등록·쓴 만큼 과금(비용 상한 필수). stage-1-api 결정 2·15의 이름, stage-1-runners의 A 실행기 공급자, PR19 범위, WEB0 비교 기준, DDL(연결·모델·단가·상한 표)이 함께 바뀐다. 결정 기록은 이 작업에서 만들지 않았다(추천: 새 결정 + 0013 일부 대체 — 설계 10절 질문 7).
5. **화면 말**: glossary 4절·stage 문서의 “Go 전송·Go 칩·Go 사용량” 화면 문구 → 13.1 대응표. DB·경로 이름은 그대로 둬도 되지만, 정책 경로(`…/policies/opencode-go/revisions`)는 AI 연결 일반화 때 이름을 다시 정할 일이다.
6. **기준점 계산**: 0013 “계정/워크스페이스 기준점”의 계산 경계를 t0 모델로(F03) — PR19.
7. **step-up**: v2 초안의 “끄기는 재인증 없이”를 철회했으므로 stage-5와 다시 일치한다(바꿀 것 없음).

## 7. 점검 기록

- **빌드**: `npm run typecheck` 0 오류 · `npm run build` 성공(경고 없음). 첫 묶음 JS 490 kB(gzip 151 kB) + 화면별 0.3~32 kB · CSS 142 kB(gzip 31 kB) · woff2 92개 약 3.0 MB · `dist/` 약 4.2 MB · `dist/fonts/`에 OFL 원문.
- **헤드리스 Edge(CDP)**: 1440 · 1366 · 1100 · 390(터치 흉내) · 320 폭, 27개 주소 — 가로 넘침 0, 화면 글자 ‘Go’ 0, 콘솔 오류 0(React Router `HydrateFallback` 경고는 고침).
- **동작 16가지**(스크립트로 클릭·입력): 이 질문만 보내기 · 응답 유실 → 결과 미확인 → 같은 키 재확인(처음 영수증 재생) · 버전 충돌 · AI 참조 끄기(회수 불가 안내 → 본인 확인 → 접수 → 표 갱신) · 폴더째 올리기(미리 보기 → 진행 → 일부 실패 → 실패만 다시) · 확인 안 된 호출 정리(근거·이유) → 지금 할 일이 “기다림” · AI 연결 추가(상한 없으면 저장 막힘, 키 다시 안 보임) · 편집자 막힘 · 첫 Tab 건너뛰기 · Ctrl+K · 한글 조합 중 무시 · 좁은 화면 `#result` → 결과물 보기. 처음 돌렸을 때 찾은 결함 3개(명령 메뉴가 `Command` 없이 열리지 않음 · 정리 대화 상자가 정리 직후 사라짐 · 응답 유실 흉내에서 변경 알림이 먼저 와 “결과 미확인”이 안 보임)를 고치고 다시 돌려 모두 통과했다.
- **사용자 개발 서버**: 사용자가 띄운 `vite --port 5199`는 건드리지 않았다(파일 저장 때 자동 갱신). 확인용 `vite preview`(4173)와 헤드리스 Edge는 시안 폴더 밖 임시 프로필로 돌렸다.

| 가운데에는 한 가지(질문 폼과 결과 글을 나란히 두지 않음) | “일에 집중”. 옛 라운드 화면은 지금 할 일 띠 + 핵심 상태 + 결과 글 + 질문 폼 + AI 작업 + 동기화가 한 화면이었다. 순서 줄과 [다음 할 일]로 이어 간다 |
| 끝나면 “○○ — 마쳤습니다” + 다음 할 일 단추로 초점 — **저절로 넘기지 않음** | P6(조용히 바꾸지 않음). 화면이 저절로 바뀌면 키보드·화면 읽기 사용자의 위치가 사라진다 |

| 추천은 **표시만** — 미리 고르지 않음 | 질문 기본값 규칙(미리 고르지 않음)과 같게 · 고르는 것은 사람(P6). “한 번에 처리”는 처리 단추 한 번 |
| 문제 상태 말 = 차례 말(나의 할 일 · AI가 하는 중 · 기다림 · + 해결됨) | 새 이름을 만들지 않음(P2) — 같은 모양 · 같은 색 |
| 역할별 상태 — 소유자만 고르는 문제는 편집자에게 “기다림”, 읽기 멤버는 모두 기다림 | F08 — 나의 할 일 수와 같은 기준(서버가 사람·권한별로) |

| J/K는 **집중 모드에서만** + “J/K 단축키” 끄기 스위치 · 한글 자판에서도 같은 자리(`e.code`) | WCAG 2.1.4(한 글자 단축키는 끌 수 있어야) · 화면 읽기 프로그램의 한 글자 탐색과 부딪히지 않게 |

| 연구 공간 틀(AI 동료 칸 포함)은 따로 불러오는 묶음 | 관리 공간 첫 묶음이 AI 동료(Select 등) 때문에 커지지 않게 |

### 11.4 계획과 어긋나는 곳(고치지 않음 — 목록만)

- **`problem.resolve`는 계획에 없는 명령**(미정): 문제 종류별 닫힌 선택지 목록 · 서버 검사 · 해결 기록 표(U3의 반영 내역/가정·결정 표를 같이 쓸지)를 U3 · U4 · U5 착수 때 정한다. 답하기 · 동기화 고르기 · 호출 정리 · 참고 갱신은 원래 명령 그대로라 두 번째 쓰기 경로는 없다.
- **연구 내용 문제를 누가 언제 찾나**: 시안은 조사 단계에서 “AI 점검 · 출처 대조”가 올린다고 그렸다. 검증 단계(verifier의 supported/partial/unsupported)와 같은 말 · 같은 기록을 쓸지 정해야 한다.
- **나의 할 일 순위(3.3)에 “풀 것” 종류**가 새로 생겼다(5순위). 승인을 막는 문제를 3순위(승인)보다 앞에 둘지는 판단 대기(N30).
- **`/p/<프로젝트>` 동작**: 현재 라운드로 넘김 → 연구 개요. U1 라우트 표와 다르다(기존 ask 링크는 라운드 주소라 그대로 동작).
- **알림 항목의 프로젝트 표시**(`slug`): WEB8 알림 표에 열이 필요하다(문구에는 여전히 싣지 않음 — 4.13).
- **읽기 묶음**: `GET P/workspace`에 연구 칸 여섯, 목록 카드에 `problems_open`, 나의 할 일 항목에 `step` · `order` — G22 · G24 확장(U1 · PR14).

### 12.2 결정과 이유

| 결정 | 이유 |
|---|---|
| 44px 규칙을 **CSS 층 밖**에 px로 | Tailwind v4는 utilities 층이 components 층을 이긴다 — 예전 규칙은 처음부터 단추의 `min-h-*`에 져서 실제로는 적용되지 않았다. rem으로 잡은 크기는 html 87.5%와 함께 줄었다 |
| 머리줄 · ⓘ · 스위치 · 체크 상자는 **누름 영역만**(가상 요소) | 보이는 크기를 키우면 390 머리줄이 넘치고, ⓘ가 있는 제목 줄이 44px로 높아진다. 머리줄은 옆 간격의 절반까지만 넓혀 이웃과 겹치지 않는다 |
| 데스크톱은 그대로(24px 바닥만) | 밀도는 사용자 결정. 마우스는 정밀하다 — WCAG 2.5.8 AA(24px)는 지킨다 |
| 못 누르는 이유: **해결 흐름은 늘, 나머지는 누르면** | 해결 흐름은 “어떻게 할지 고르세요”가 다음 행동을 알려 주는 한 줄(16.4-3). 질문마다 긴 이유를 늘 보이면 글이 다시 많아진다(14절) — 누른 사람에게만 그 자리에 |
| 화면이 바뀌면 **새 화면 제목**으로 초점(테두리 없음) | 키보드 · 화면 읽기 사용자가 새 화면 처음부터 읽는다. 제목은 조작이 아니라 테두리를 그리지 않는다(#main · #now-title과 같은 규칙). 판 · 대화 상자가 닫히며 radix가 초점을 되돌린 뒤에 옮겨야 이긴다 |
| 처음 불러올 때 · `#조각` · 뒤로 가기에는 초점을 옮기지 않음 | 첫 Tab = 건너뛰기 링크(O9), `#조각`은 그 자리가 초점, 뒤로 가기는 읽던 자리 |
| 문서 제목 = 빵부스러기 계산 그대로 | 새 이름을 만들지 않음 — 화면 말과 같음(‘Go’ 없음) |
| 11px 바닥은 `max(0.75rem, 11px)` | 사용자가 브라우저 글자를 키우면 rem 쪽을 따른다(dynamic-type) |
| 새 프로젝트를 테두리 단추로 | 관리 공간의 주 동작은 나의 할 일 첫 줄 — 4차 “맨 앞 하나만 채움”과 같은 규칙. 사이드바에도 있어 찾기 어렵지 않다 |
