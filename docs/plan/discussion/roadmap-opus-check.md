## 2. OpenCode 반영 지시 (`docs/plan/roadmap.md`)

1. 2절: 97은 유지. 표 아래에 "SEL ID 기준, 단계 문서는 누적 합계를 쓰지 않고 이 표를 가리킨다", "단계 문서의 '0단계 11+계획 11'은 SEL-20 중복으로 1씩 많다. 바른 값: 2단계 뒤 53, 3단계 뒤 62, 4단계 뒤 71, 5단계 뒤 86, 6단계 뒤 97", "SEL-32 이후 존재 여부는 등록 직전 Linear로 확인"을 넣는다. 40줄 설명을 이것으로 바꾼다.
2. 2절: 여유 163 안에 미리 잡을 예비분(U4·U1 분할 +1~2, T1 결함 PR, 단계별 결함·보안 PR)을 적는다.
3. 3.1: 4단계 줄을 "PR23 → PR24, PR25(PR6·U4 뒤, PR23과 독립) → U7~U12"로.
4. 3.1·3.2: WEB0을 "번호는 5단계, 실행은 2단계 PR4·13의 계약 픽스처 직후"로 옮기고 "결과가 TS 이식이면 2~4단계 구현 언어를 다시 정한다"를 실패 열에 쓴다.
5. 4절 위험 표에 네 줄 추가: 코어 이중 구현, 사용자 플러그인 유입·배포 때 쓰기 차단, Workers Free 25초 대기 구현, R2 결제 수단 요구 가능성(각 대응·확인 시점은 1절 R8).
6. 5.1에 2026-11-05 "Cloudflare 무료 요금제로 설계", 저장소 공개 유지, 0단계 계획 확정을 추가.
7. 5.2를 (가) 비용·되돌리기 결정과 (나) 단계·전환 승인 두 표로 나눈다. (가)에는 R12 목록만, (나)에는 0.16.0 배포·기본 화면 전환·각 단계 진입·웹 이전·실제 자료 업로드/운영 전환/유료 전환 경계·6단계 완료를 둔다.
8. 5.2에서 W1·R1 실시 여부와 무료 한도 경보 기준을 뺀다. A 비용 상한 행에 "한 번 정하면 3~6단계가 승계, 다시 묻지 않음"을 쓴다.
9. 6절 1번을 "구성은 맞고 SEL-20 중복으로 1 많음(바른 값 62)"으로 고친다.
10. 6절 2·4번에 "6단계 최종 대조로 수정 중"을 표시한다.
11. 6절 3번을 규칙으로 바꾼다: Linear 제목 `[N단계 번호]`, 문서 안 참조 `SN-번호`.
