| 2 도메인, S5:247 | 동의 | 구매 비용·메일 발신/패스키 RP·OAuth redirect·쿠키·사용자 링크의 이전 비용이 있어 적절하다. 보유 도메인이 실제 있다는 전제 없이 선택지를 제시하고 도메인 소유/관리 주체와 prod/staging 이름을 정한다. |
| 3 비용 상한·결제 계정, S5:248 | 수정 | 사용자 확인이 필요하다. **인프라 월 예산/경보·추가 유료 전환 허용·A run/단계/프로젝트 누적 상한·구독 비용**을 구분한다. $20은 현재 설계로 청구액 강제 상한을 보장하지 못함을 밝힌다. 무제한을 기본 대안으로 둘 필요가 없고 첫 유료 시험 전 시험 상한도 정한다. |
| 4 메일 발신 사업자, S5:249 | 수정 | 일반적인 Resend/Postmark/SMTP 선택은 구현자가 근거로 정할 수 있다. **유료 계약·발신 도메인/DNS 관리 주체·외부 알림에 포함할 정보**만 사용자 확인으로 남긴다. 무료량의 일일 한도·인증 메일 포함 조건을 반영한다. 발신 평판의 이전 비용은 설명하되 공급자 선택이 무조건 불가역적이라고 과장하지 않는다. |
| 5 이전 대상·시점, S5:250 | 동의 | 실제 프로젝트별 사본/업로드·동결·운영 활성화·새 쓰기 후 복구 손실 경계는 비용/되돌리기 어려운 확인 대상이다. 합성 검증을 먼저 끝내고 **구체적 slug/범위와 복구 절차가 검토 가능한 시점**에 허용받는다. 전체 일괄 이전을 기본으로 확대하지 않는다. |
| 6 A 상시 실행, S5:251 | 수정 | VPS 추가 결제·운영 주체는 사용자 확인 대상으로 적절하다. **로컬 runner 기본 구현은 이 단계 설계로 진행**하고, VPS가 실제로 필요해질 때 구체적 월 비용/보관 범위/중단 방법과 함께 선택받는다. 로컬 구현 방법 자체를 다시 승인받을 일로 만들지 않는다. |
| 7 백업 보존·위치, S5:252 | 수정 | 보존을 줄여 복원 가능 기록이 사라지거나 유료/교차 계정 보관이 생기는 경계는 적절하다. 다만 ‘가능하면 교차 계정’ 대신 **정확한 대상 계정·암호키 관리·포함 데이터·복구/정리 조건·추정 비용 산식**을 제시한다. 일 30/월 12는 제안값이며 실제 변경량 없이 $1 미만을 보장하지 않는다. |
| S5:254의 ‘나머지는 되돌리기 쉬움’ | 수정 | 라이브러리/runner 구현은 통상 구현자 결정이 맞지만, **인증 RP/도메인·계정 복구 방식·실제 지원 기능 제거**까지 모두 쉽게 되돌린다고 일반화하지 않는다. WebMCP는 날짜 있는 기술 재검토로, 비용/실제 자료/계정 잠김 위험을 바꾸는 변경은 해당 경계로 분류한다. |

## 6. 실제 프로젝트·설정 내용 유입 여부

| 확인 항목 | 판정 | 확인 범위·결과 |
|---|---|---|
| 기본 경로·placeholder, S5:83, 247 등 | 동의 | `~/.pes/credentials`는 향후 평문 저장 금지를 설명한 경로이고 `pes.<도메인>`·토큰/URL 예시는 placeholder다. 경로 문자열 자체를 실제 디렉터리 열람이나 내용 유출로 판정하지 않는다. |
| 실제 자료로 식별되는 내용 | 동의 | **S5 280줄에서 실제 프로젝트 slug/목록·본문/질문/답·비밀키·실제 설정값을 발견하지 못했다.** ‘1명·3프로젝트·500MB·5GB’는 근거 없는 비용 가정으로 표시돼 있어 추정 근거 보완 대상이며, 그것만으로 실제 폴더 실측값이라고 단정하지 않는다. 2MB fixture는 S0:23의 합성 시험 기준이다. |
| 확인의 한계 | 수정 | ‘실제 자료 없음’은 **초안에서 식별되는 실제 내용 없음**으로 한정한다. 실제 디렉터리를 읽지 않았으므로 작성자의 과거 접근 이력이나 예시 수치의 출처까지 보증할 수 없다. 이를 확인한다는 이유로 금지된 실제 디렉터리를 열지 않는다. |
| 향후 이전/운영 산출물, S5:135, 261 | 수정 | 실제 이전 manifest·경로·검증 보고서·메일 수신자·백업·로그를 **공개 `docs/plan`이나 CI artifact에 저장하지 않게** W9/10/14에 귀속한다. 공개 PR에는 합성 재현·민감 내용 없는 결과만 남긴다. 실제 slug 허용은 연구 자료의 공개·메일 본문 노출 허용과 다르다. |

이 검수는 설계 대조다. 반대 항목과 누락 선행/완료 조건을 반영한 뒤, 표·본문·게이트·비용 산식을 함께 재대조해야 한다. 실제 배포·지출·자료 이전은 이 검수로 승인된 것이 아니다.
