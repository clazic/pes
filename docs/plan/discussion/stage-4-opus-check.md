## 3. OpenCode 반영 지시 (`docs/plan/stage-4.md`)

공통 규칙: 1단계 계약은 번호로 가리키고 옮겨 적지 않는다. 문서는 약 260줄 안.

1. 머리말: 0~3단계 게이트 전제, W1·R1은 필수 아님. 8행을 "본문에 실자료 없음"으로. "이미 정해진 것" 중 새 제안(판 완료 권한·해제 기한·opt-in·유지 기간)은 "4단계 제안"으로 표시.
2. 2.1: 완료 조건 = 미종결 run 없음·6단계 현재 승인·stale 없음·필수 응답 없음, 서버 재검사, 한 tx. 해제 때 승인·stale·포인터 처리와 `archived` 범위. 옛 프로젝트 1판 완료 조건(Z2).
3. 2.2: 종류별 실제 계보 열 표(SQL:340·614·754, 가정·출처는 이월 기록). 공통 결정은 "원본 새 버전"과 "참조 기준 갱신" 구분. 결과물·출처·각주·파일과 `next_round_task` 이월 규칙(B02·B03).
4. 2.2 "기록" 행과 6절: `edition_carryovers`+`completed_snapshot_id`로 확정, 이유를 `docs/plan/decisions/`에 기록, 제약·서비스 책임과 새 마이그레이션 시험(D03).
5. 2.3: 한 비교 = 한 사건 경계, 페이지 사이 유지, epoch 변경 시 재조회, 열린 라운드 포함.
6. 2.4: 묶음 ID·기반 버전·후보 목록·원자 채택. 미검증 가정 대안 허용. 진행 중 run 안 제안 vs 새 유료 run(사람 시작·정책·예약) 구분, "요청 시 추가" 뜻 통일.
7. 2.5: 작업 AI도 반대 제기 가능, 자기 점검/독립 검토를 표시로 구분, 독립 검토는 필요할 때만 reviewer run. 확인은 대상 버전에 고정, 승인 명령이 같은 tx에서 검사.
